## 1. 셸 시작의 흐름

셸 시작은
`/etc/zprofile -> path_helper -> ~/.zprofile`
시스템 전체에 적용되는 파일부터 사용자 개인으로 오기까지 점점 지엽적으로 적용된다.
~/.zprofile에 있는 내용이 앞에 내용을 이김.

## 2. PATH

PATH는 앞에서부터 찾고, 처음 찾은 걸 실행!!!!
homebrew에서 git을 깔아 사용하려 했지만 우선순위가 뒤에 있어 which git을 했을 때,
시스템 기본 git 경로가 나왔다.

Homebrew 경로 + 기존 PATH 전부로 기본 설정(.zprofile)을 바꿔놓으면 git을 사용할 떄,
다운로드한 git 버전이 사용된다.

## 3. 심볼릭 링크와 깨진 링크

심볼릭 링크는 일종의 표지판이다. (원본의 경로를 가리킴)
하드링크처럼 그 파일 데이터를 가르키는 것이 아닌 '바로가기'처럼 -> 기호로 링크를 걸어주는 것이다.
디스크 관리에 용이하다.

깨진 링크는 표지판은 있으나 목적지 폴더나 파일이 사라진 경우를 말한다.
이런 경우에 오류가 생김!

## 4. 따옴표 3종류

명령어를 사용할 떄, 따옴표의 사용법이 모두 다르다.
"" <- $변수 와 $(...)을 해석함
'' <- 문자 그대로
`` <- 안의 명령 실행

## 5. git config 범위 3단계

`git config`
아래로 갈수록 적용 범위가 줄어들음
아래가 위를 이김

--system 이 컴퓨터의 모든 사용자
--global 나의 모든 저장소
--local 지금 이 저장소 하나

## 6. SSH 개인키 vs 공개키

두 키의 권한 차이
rw------- 개인키
rw-r--r-- 공개키

개인키는 SSH 서버에 연결할 때, 서버에게 나 자신이 맞음을 인증하는 주민등록증 같은 것이다.
다른 사용자들 r(read)이 없는 이유!

## 7. Git의 파일 추적

git은 빈 폴더를 추적하지 않는다.
따라서 커밋이 안됨!
관례용으로 `.gitkeep`이라는 이름의 파일을 만든다.

-> 안에 구조 구성용 파일이라도 만들어야 커밋을 하고 푸쉬할 수 있다.
