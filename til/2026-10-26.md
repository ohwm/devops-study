## 1. 프로세스 기본

프로세스 = 실행 중인 프로그램, 커널이 `task_struct`로 관리
`/proc/<PID>/status` (State, PPid, Uid)
`ps -ef`, `ps aux`, `ps -o pid,ppid,stat,cmd -p <PID>`, `pgrep -a`
`echo $$` = 현재 셸 PID, `$!` = 마지막 백그라운드 PID
fork → exec: PPID = 셸의 PID인 이유, exec는 PID 유지
STAT: R / S / T / Z, `+`(foreground), `s`(session leader)
S 상태 = 대기 큐(wait queue), 스케줄러는 run queue에서만 고름 → %CPU 0

## 2. 시그널

`kill`은 시그널을 보내는 명령
SIGHUP 1 / SIGINT 2 / SIGKILL 9 / SIGTERM 15 / SIGSTOP 19 / SIGCONT 18
SIGTERM은 핸들러가 있어야 정리 후 종료
`$?` = 128 + 시그널 번호 (130 / 143 / 137)
`$?`는 셸이 wait한 포그라운드 명령의 종료 코드
T 상태에 보낸 SIGTERM은 pending → SIGCONT 후 처리, SIGKILL은 즉시
Ctrl+C: 0x03 → ssh → pty → 커널 line discipline → 포그라운드 프로세스 그룹에 SIGINT

## 3. Uid 4개

Real / Effective / Saved / Filesystem
setuid 프로그램(passwd)은 exec 때 Effective UID만 0으로 바뀜

## 5. 패키지 관리

apt(검색·의존성·다운로드) vs dpkg(설치·기록)

manual vs auto, `autoremove`
`dpkg -L`, `dpkg -S`, `wc -l`
`procps` = /proc를 읽는 도구들
